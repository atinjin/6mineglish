# SIXMIN

BBC 6 Minute English 한 편을 매일 하나씩, **듣기 → 섀도잉 → 출력** 순서로 끝까지 끌고 가는 iOS 학습 앱.
도중에 걸린 단어와 문장은 카드가 되고, 외울 때가 되면 알림이 먼저 찾아온다.

디자인 시안은 [`design/sixmin-design.html`](design/sixmin-design.html)에 있다. 화면 11종과 색·타입·간격
토큰, SM-2 간격 표, 알림 규칙이 모두 여기서 나왔다.

## 열기

```
open SIXMIN.xcodeproj
```

Xcode 16 이상, iOS 17.0 이상. 외부 의존성은 없다. 서명 팀만 지정하면 바로 빌드된다.

실기기에서 돌려야 한다. **시뮬레이터에는 기기 내 음성 인식 모델이 없어 스크립트 생성이 실패하고**,
마이크 녹음도 제대로 확인되지 않는다.

## 첫 실행 흐름

1. 앱이 BBC 공식 RSS를 읽어 에피소드 목록을 채우고, 아직 안 한 최신 편을 오늘 자리에 배정한다
2. 오늘 화면에서 오디오가 자동으로 내려받아진다 (기본값 Wi-Fi에서만)
3. **스크립트 만들기**를 눌러 기기 안에서 문장과 타임스탬프를 생성한다 — 6분짜리 기준 1~2분 걸린다
4. 듣기 → 섀도잉 → 출력 순으로 진행한다. 출력 단계에서 저장한 표현이 복습 카드가 된다

## 구조

```
Sources/
  App/          앱 진입점, 탭 구성
  Design/       색·서체 토큰, 루틴 단계 정의
  Core/         날짜 키, 파일 보관소, 설정
  Models/       SwiftData 모델 (Episode, TranscriptLine, ShadowTake, StudyCard, RoutineLog)
  Services/     RSS, 다운로드, 재생·녹음, 음성 인식, SM-2, 알림, 백그라운드 갱신
  Components/   파형, 히트맵, 칩·버튼
  Views/        화면 9개
Resources/
  Info.plist    권한 문구, 백그라운드 모드, BGTask 식별자
design/
  sixmin-design.html   화면 설계와 디자인 시스템
```

### 핵심 규칙이 사는 곳

| 규칙 | 파일 |
|---|---|
| SM-2 간격 계산, 하루 상한, 큐 구성 | `Services/SRS.swift` |
| 카드 종류와 한 단어에서 세 장이 나오는 규칙 | `Models/StudyCard.swift` |
| 알림을 보낼 때와 보내지 않을 때 | `Services/NotificationScheduler.swift` |
| 오늘 에피소드 배정, 연속 일수 | `Services/StudyPlanner.swift` |
| 음성 인식 결과를 문장으로 묶는 경계 | `Services/TranscriptionService.swift` |

## 스크립트를 얻는 방식

오디오는 BBC가 재사용 조건을 명시해 공개한 **공식 RSS**에서 받는다.
스크립트는 그 오디오를 기기 안 `Speech` 프레임워크로 처리해 **앱이 직접 생성**한다 — BBC 웹페이지의
편집 저작물을 저장하거나 재가공하지 않는다.

설정의 **기기 안에서만 생성**이 기본 켜짐이다. 끄면 애플 서버로 오디오가 전송되므로, 끌 때만
그 사실을 알고 끄면 된다. 공유·배포 기능은 넣지 않았고, 내보내기는 **사용자가 직접 쓴 카드**만
대상으로 한다.

## 구현된 것

- BBC RSS 수집, 에피소드 자동 배정, 오디오 다운로드와 캐시
- 실제 오디오를 디코딩한 파형 (`AVAssetReader`로 구간별 피크를 뽑아 파일 캐시)
- 3단계 루틴 타이머, 문장 하이라이트가 따라가는 재생기
- 문장 구간 반복 + 녹음, 원본(블루)과 내 목소리(오렌지) 파형 상하 대조
- 문장 카드 / 단어 카드(이해·생산·듣기) / 짝 맞추기 세 가지 복습
- SM-2 간격 반복, 카드에 붙은 원본 구간과 내 녹음 재생
- 완료 정도를 담는 히트맵, 연속 일수, 성숙 카드 집계
- 조건부 로컬 알림 (하루 2건 상한, 완료 시 침묵, 알림에서 바로 복습·미루기)
- CSV 내보내기, 오래된 오디오 정리

## 아직 확인이 필요한 것

이 코드는 **Xcode에서 빌드·실행 검증을 하지 않았다.** 작성 환경에 Swift 툴체인이 없었다.
처음 열면 컴파일 오류가 남아 있을 수 있으니 그 전제로 봐야 한다.

기능 면에서 먼저 실측이 필요한 부분:

- **음성 인식 정확도.** 섀도잉 화면과 단어 카드의 구간 발음이 전부 문장 단위 타임스탬프에 기대고
  있다. 실제 6분짜리 mp3로 문장 경계가 제대로 잡히는지 확인하는 게 첫 순서다. 결과가 나쁘면
  `TranscriptionService.makeDrafts`의 묶는 기준(문장부호 · 0.65초 공백 · 18단어)을 조정하거나,
  섀도잉 UI 자체를 다시 봐야 한다
- **긴 오디오의 온디바이스 인식.** `SFSpeechURLRecognitionRequest`가 6분 파일을 한 번에 처리하는지,
  중간에 끊기면 분할이 필요한지
- **단어 구간 추정.** 지금은 문장 안 글자 위치 비율로 어림한다(`CardFactory.wordSegment`).
  실제로 그 단어가 들리는지 귀로 확인해야 한다
- 배터리와 처리 시간 — 백그라운드에서 스크립트를 생성하도록 넓힐지는 실측 후 결정
